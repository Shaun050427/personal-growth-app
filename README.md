# Personal Growth App

个人全方位成长系统的公开前端仓库。静态页面由 GitHub Pages 托管，私人数据不存放在本仓库。

部署方法见项目包根目录的 `README_部署说明.md`。

## 数据安全

- 不要向本仓库提交个人记录。
- 不要向本仓库提交 GitHub Token。
- 个人数据仅通过浏览器写入私有仓库 `personal-growth-data`。


## 成长决策功能

- **每周复盘**：首页和导航栏均可进入；周一至周日汇总科研推进、卡点、课程与日程计划、清单记录、训练、心法及成果。未来记录不计入实际推进，未记录与未勾选明确区分。
- **Markdown 导出**：先预览，再复制或下载给 ChatGPT；附有证据、项目取舍、最多三个下周重点及停止条件的分析提示。可排除训练，身体数据默认不纳入。没有模型 API 调用。
- **独立草稿**：复盘输入自动保存到当前浏览器，按周和数据仓库隔离；只有“确认保存复盘”才进入个人数据备份与云同步。选择历史周可查看、修改或删除已保存复盘。
- **项目评估**：中长期项目增加预期成果、工时和费用/算力预算、审查日期、奖励资格、基线差距、个人优势、可迁移价值、继续/终止条件和决策依据；新增“已终止”状态。到期项目在首页和复盘中提示，不自动终止。
- **参赛评估入口**：Kaggle / 天池日报的“评估是否参赛”预填项目名称、链接和奖励信息。仅保存后才创建项目，同一链接优先编辑已有项目；日报相关度不代表获奖概率。
- **成果资产**：记录报告、竞赛经验、代码、笔记和作品的日期、链接、证据与复用方式，可关联项目、搜索、筛选、编辑或删除。删除项目会解除成果关联，保留成果本身。

## 同步兼容与验证

继续使用原有 `personalPlanner_v2` 数据键与 V2 数据结构，新增 `assets` 和 `weeklyReviews` 两个可选数组。旧备份及旧云端数据缺少这些字段时按空数组读取；导入/历史恢复会正确清除不属于该版本的新记录，未知字段原样保留。

同步使用稳定字段顺序的指纹，旧同步元数据在首次启动时兼容迁移。保存已同步的数据快照作为三方合并基线，同一记录的独立字段、独立记录和清单勾选可以合并；覆盖同一字段、删除与编辑冲突或不兼容排序仍需明确选择。浏览器支持 Web Locks 时串行协调标签页上传；GitHub 文件 SHA 仍用于阻止过期写入。上传中发生的新编辑继续标记为未同步。遇到无法自动合并的内容，两边副本保存在本机并可一起下载。

升级后请关闭旧版本标签页，再重新打开网站，以免旧代码在其他标签页同步。独立复盘草稿只在当前浏览器保留，重要复盘请点击确认保存。

验证命令：

```sh
node --test tests/test_growth.js
python -m unittest discover -s tests -p 'test_*_report.py'
```

前端测试使用模拟的 GitHub 响应验证同步与保存逻辑，不读取或改写实际私人记录。
